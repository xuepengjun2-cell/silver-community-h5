# 银发活动 SOP 与活动相册平台

## 生产代码源与发布边界

生产环境以 GitHub `main` 的明确 commit 为唯一代码源。服务器只保留运行时环境、数据库、上传临时目录和 PM2 进程，不直接在服务器编辑业务代码；TOS/CDN 只接收从 GitHub commit 构建并校验过的静态发布包。

活动相册的图片、视频和上传会话数据属于生产运行时数据，不随代码发布覆盖。代码发布前必须完成服务器/TOS/CDN 备份，发布后必须做公网入口、API 健康、登录权限和活动相册链路验收。

- 本阶段不修改 `miniapp/`，不上传新的客户端包，不重新提审或发布。若某项需求必须改客户端，先说明原因、影响和可行替代方案，再由用户决定是否另行启动客户端更新。
- 服务端改动保持现有客户端调用的路径、鉴权方式、响应字段、媒体类型、素材原编号、分享链接和 CDN 地址兼容；客户端收到上传成功或处理完成时，对应素材必须真实可用。

- 每次服务端发布前检查旧客户端的登录、相册照片/视频展示、上传处理、分享及保存链路；涉及客户端本地压缩、页面状态、断网重试的限制，不能宣称仅改服务端就能修复。
- 优化继续按 GitHub 提交、CI、受控发布和现网回读执行；不回退数据库、客户原片或既有服务器优化。

## 本地开发与检查

需要 Node.js 18 及以上版本。本地启动前配置隔离 MySQL 和媒体存储；自动化测试使用项目内的假 MySQL/TOS 环境，不需要生产凭据。

```bash
npm ci
npm run check
npm start
```

本地地址：`http://localhost:5174`，后台地址：`http://localhost:5174/admin`。实际数据和账号由本地配置决定，历史演示账号不能用于判断生产登录状态。
