# 活动相册 · 个人主体微信小程序开发版

AppID：`wx58bef83060b92027`。这是与银发社群 H5 共用数据和主办方账号的原生小程序开发工程，不使用 `web-view`，不存 AppSecret、TOS 密钥或密码。

## 双入口

- 主办方：正常启动即看到原 H5 账号/密码登录表单；有效登录态自动进入工作台。管理员、运营、普通成员按服务端现有权限管理活动相册；只读账号仅进入活动库和精彩案例，不请求相册管理列表。活动库支持名称、城市、类别、简介及标签关键词搜索。无需复制或粘贴 H5 链接。
- 客户：点击某个相册的分享卡片 → 匿名查看该相册、照片和视频；符合交付格式的素材可保存到系统相册。分享路径指向 `pages/album/index?id=...`，不经过主办方登录。
- 活动库和精彩案例以封面卡片展示，客户可免登录预览已发布内容。活动库新增真实 PDF 执行方案下载：需登录且该活动允许下载；PDF 保存到小程序本地后打开文档菜单。精彩案例新增照片/MP4 保存到系统相册及文档下载，均先走原 H5 的登录鉴权与下载审计，分享不放开匿名下载；案例视频播放器支持竖屏全屏。外部链接素材仍未在小程序内实现下载。原 H5 的编辑/审核、评论及总部权限/访问日志尚未完整迁入。

## 客户保存的实际边界

- 小程序相册和单素材分享可匿名打开；点击“保存到手机相册”后，先复核相册仍已发布且允许分享，再经现有公开接口记录下载，随后从已登记的项目 CDN 下载并调用微信保存照片/视频接口，不把临时 TOS 签名地址展示给客户。
- 只有项目 CDN 上的 JPG/PNG 和有明确文件大小、且不超过 200 MB 的 MP4，才显示为可直接保存。MOV/HEIC/SVG 等原件不能据此宣称可一键保存；按钮会说明原因。新上传视频由服务端生成交付版 MP4（接口已于 2026-09-22 随后端部署上线），旧素材需补交付版。
- 2026-09-22 只读核对现网一个已发布相册：1 张 JPG、36 个视频，其中仅 2 个 MP4，其余 34 个为 MOV。1 张照片和 2 个 MP4 的 CDN `HEAD` 返回 200、类型与长度正确；这只证明交付文件可访问，**尚不等于已在 iPhone/安卓/鸿蒙真机完成保存验收**。该相册已于 2026-09-22 完成交付版替换，36 个视频均为带首帧的 MP4。

## 新上传的处理边界

1. 小程序 `wx.chooseMedia` 选择照片/视频后，本机调用 `wx.compressImage` / `wx.compressVideo`；视频压缩后仍超过 190 MB 时，明确要求分段，不上传原片。
2. `wx.uploadFile` 向后端新增的鉴权入口上传压缩后的临时素材；上传域名必须在该 AppID 后台单独配置。服务端串行转码：照片统一 JPEG；视频统一 H.264/AAC MP4、720p 上限、25 fps、`faststart`，目标约 155 MB，最终严格小于 190 MB，最长 40 分钟。时长过长/码率过低/输出不合格时拒绝发布，并提示分段。
3. 转码成功后才上传 TOS、校验对象大小并将媒体写入相册；视频任务有鉴权状态查询。服务端临时源文件在完成或失败后删除，新的小程序上传不保存云端原视频。旧素材仍保留原件；H5 新上传有独立的受控压缩开关，详见《交付版视频实施方案》。
4. 服务端依赖 `ffmpeg`/`ffprobe` 和 TOS，单队列处理以保护服务器。后端于 2026-09-22 部署；2026-09-25 合并 PR #2 后，仅替换现网 `silver-new` 的 `server.js` 并重载 PM2 `silver`，文件 SHA-256 为 `1f6d62af34a32f6c5d3ff454f3114622d13210708ff6630ccc89d9af85b7750a`。`package.json` 本次只新增测试脚本，生产依赖未改。发布后本地及公网健康检查正常，约 5.4 GB 可用磁盘（已用 89%）；但仍未用真实样本完成画质/耗时/真机验收。
